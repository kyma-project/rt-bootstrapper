# Risks and Technical Debt

## Risks

| ID      | Risk                                                                                                                                                                      | Probability                                             | Impact                                                                | Mitigation                                                                                                                                                                                                                    |
|:-------:|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------|-----------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| R-1     | Unmanipulated Pods – Pods created while the webhook is down miss all manipulations.                                                                                   | Medium (webhook restarts are routine)                   | High (Pods may fail to pull images or communicate with BTP services)  | No automated process exists. Manual intervention is required: identify Pods missing the `rt-bootstrapper.kyma-project.io/modified: "true"` annotation and restart them so that the webhook applies the manipulations during re-creation. |
| R-2     | Config read latency – Every webhook invocation performs one API server GET for the ConfigMap. Under high Pod-creation rates this adds latency and load.               | Low (Kyma module deployments are bursty but infrequent) | Medium (admission webhook timeout breach causes Pod creation failure) | Acceptable at current workload volumes. Mitigation path: introduce an informer-based cache with TTL if benchmarks show a problem.                                                                                             |
| R-3     | Secret sync stale window – A new namespace may not receive the pull secret before its first Pod is scheduled, if the Pod is created very quickly after the namespace. | Low                                                     | Medium (Pod fails to pull image)                                      | The `createNsPredicate` triggers an immediate reconcile on namespace creation. The risk window is the controller's reconcile latency (milliseconds under normal conditions).                                                  |
| R-4     | caBundle patch race – Multiple cert rotation events in rapid succession could cause conflicting patches to the `MutatingWebhookConfiguration`.                        | Low                                                     | Low (retry loop handles conflicts)                                    | `BuildUpdateCABundle` wraps the patch in `RetryOnConflict`; the API server's optimistic concurrency ensures eventual consistency.                                                                                             |

## Technical Debt

| ID      | Description                                                                                                                                                                                                                                                                                                   | Impact                                                                                     | Planned Resolution                                                                                                                                                                                                                                                         |
|:-------:|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| TD-1    | Interim resource synchronization via KIM labeling – The current architecture for syncing pull secrets, `ClusterTrustBundle`, and webhook configuration from KCP to Kyma runtimes relies on labeling `Runtime` CRs to trigger KIM reconciliation. This introduces an indirect signaling dependency on KIM. | Medium – changes to shared resources take longer to propagate and require KIM to reconcile | A long-term architecture (documented in `docs/contributor/appendix/resource-synchronization.md`) will replace this with a direct controller loop that propagates configuration changes to runtimes without KIM involvement, using a dedicated CR for lifecycle management. |
| TD-2    | No in-process config cache – The ConfigMap is re-read from the API server on every webhook invocation. This was a deliberate simplicity trade-off.                                                                                                                                                        | Low at current scale; could become Medium at very high Pod creation rates                  | Introduce an informer-based cache when benchmarks indicate a need.                                                                                                                                                                                                         |
| TD-3    | gocyclo suppression on `main()` – `cmd/main.go` has a `//nolint:gocyclo` directive. The main function is long and handles multiple concerns (flag parsing, cert setup, manager setup, controller setup, webhook setup).                                                                                   | Low (no runtime impact; maintenance concern)                                               | Refactor main into smaller initialization functions grouped by concern.                                                                                                                                                                                                    |
